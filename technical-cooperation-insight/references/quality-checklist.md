# 质量检查清单

## 关键检查

- [ ] 团队或个人名称与用户称谓及材料一致。
- [ ] 团队介绍只包含材料支持的身份和贡献事实。
- [ ] 材料中的主要研究贡献均出现在“主要技术事实”和“团队技术能力”中。
- [ ] 技术事实写在合作判断之前。
- [ ] 重要量化结论均有来源引用、页码或行号。
- [ ] 材料事实、能力判断、合作建议和参考示例没有混写。
- [ ] 除非用户要求更多，合作建议不超过4个。
- [ ] 每个合作方向对应具体技术挑战，而不是宽泛的联合项目。
- [ ] 每个方向均包含具体合作内容、参考示例和对目标领域的可能帮助。
- [ ] 每个方向均与团队已经展示的能力高度匹配。
- [ ] 未将材料中的未来方向直接写成团队成熟能力。
- [ ] 未将参考示例写成团队已有成果。

## 语言检查

- [ ] 未使用“近期关注到”“一页结论”“技术资源调度建议”等生硬表达，除非用户明确要求。
- [ ] 未使用泛化AI口号、过度赞扬、宣传语言或戏剧化结论。
- [ ] 未使用夸张比喻、拟人化、强行对比以及“能力飞轮”“技术引擎”等空泛词语。
- [ ] 未使用反问、设问、自问自答或连续问题引出观点。
- [ ] 未滥用“这意味着”“值得关注的是”“更重要的是”等模板化过渡词。
- [ ] 标题简单自然，正文以陈述句和直接技术语言为主。
- [ ] 合作建议数量少而精准，没有追求面面俱到。
- [ ] 推断性的业务影响使用“可能”“有望”“可验证”等措辞。
- [ ] 已专门通读一次，删除明显AI化、宣传化、空泛或过度修饰的句子。

## 文档检查

- [ ] 插图与关键观点直接相关，并有准确图注。
- [ ] 未使用装饰性或重复图片。
- [ ] Word文档采用简单格式，并已完成渲染和逐页检查。
- [ ] 最终文档没有文字截断、元素重叠或异常分页。
