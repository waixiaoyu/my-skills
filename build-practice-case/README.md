# 优秀实践案例生成

`build-practice-case` 用于把真实工作过程和已有成果整理为有证据支撑的优秀实践案例。案例的主角应是可复用的方法、流程、Skill 或小工具；具体项目或交付物用于证明其如何发挥作用，而不是替代案例主线。

## 适合场景

- 将内部方法、流程、Skill 或小工具整理为经验交流、优秀实践申报或管理汇报材料。
- 从需求记录、规则文件、过程说明、截图、数据、用户反馈和已有交付物中提炼可验证亮点。
- 需要明确区分材料事实、能力判断、后续建议和版式包装，避免把推测写成既有成果。

## 需要提供的内容

尽可能提供案例对象、目标受众和用途，以及能够支撑判断的原始材料，例如过程记录、规则文件、截图、原始需求、数据、成果文档或用户反馈。

如果材料已经足够，skill 会直接推进；只有缺少的信息会实质影响案例内容或交付形式时，才会询问补充。默认生成 Word 文档；如案例明确用于现场展示或用户提出演示需求，会先确认是否改为 PowerPoint。

## 输出内容

默认案例包含四个部分：

1. 当前痛点
2. 分析和对策（含具体实例及实现过程）
3. 成果
4. 改进点

在写作前会建立内部证据台账，逐项核对结论的材料来源和边界。只使用材料实际支持的价值与结果；没有量化数据时采用可核验的定性描述，不补造指标、界面、实施范围或评价。

## 推荐提问方式

```text
请使用 build-practice-case。

请根据以下过程记录、规则文件、截图和最终交付物，整理一份用于内部经验交流的优秀实践案例。
案例对象是“……”，受众是“……”。请突出材料能够证明的流程改进和复用价值，区分事实、判断和后续建议；默认输出 Word。
```

详细执行规则见 [`SKILL.md`](SKILL.md)。
