# 论文周报小节撰写

使用这个 skill 为已经入选最终周报的一篇论文生成中文 Markdown 小节。它不是候选筛选、论文抽取或评分工具；代码框架仍负责抓取、清洗、复评、算分、入选、排序、分层、组装整篇周报和保存发布结果。

这个 skill 的边界很窄：一次只处理一篇 `selectedPaper`，输出该论文可直接拼进最终周报正文的条目，以及最后完整论文清单可复用的一句话介绍。

## 设计结论

把前序讨论沉淀为这些执行原则：

- 不在推荐列表生成阶段调用。列表生成阶段通常只有标题、作者、分类和摘要，证据不足以稳定生成最终周报小节。
- 不在候选筛选、周报复评或入选决策阶段调用。那些阶段可以继续由现有 prompt 和代码框架处理。
- 在 `selectedPapers` 已确定后调用。每篇最终入选论文调用一次，输出一个稳定的小节。
- 不重新发明最终周报 prompt。这个 skill 抽取的是现有最终周报生成 prompt 里的“单篇论文正文条目规范”。
- 代码框架继续负责全局结构：标题、YAML front matter、报告导读、本周趋势判断、分层排序、推荐阅读顺序和完整论文清单。

## 调用位置

在最终周报生成链路中使用：

1. 代码生成推荐列表。
2. 代码选择周报候选并完成周报专用复评。
3. 代码根据阈值、保底数量、排序和阅读层级确定 `selectedPapers`。
4. 对每篇 `selectedPaper` 调用一次这个 skill。
5. 代码把每篇返回的 `section_markdown` 拼入「本周必读」「值得跟进」「快速扫读」等层级。
6. 代码再生成或组装报告导读、本周趋势判断、推荐阅读顺序和完整论文清单。

## 输入

输入必须是一篇已经入选最终周报的论文，而不是候选列表。至少提供：

- `report_context`：读者、主题、证据模式和展示策略。
- `section_context`：当前论文在周报中的层级、序号和入选方式。
- `paper`：标题、作者、链接、摘要、已有分析、周报复评结果，以及可选的原文摘录。

需要字段级契约时，读取 [references/section-contract.md](references/section-contract.md)。

## 输出

只输出 JSON，不输出完整周报。核心字段：

- `section_markdown`：这一篇论文的 Markdown 正文小节。
- `list_item`：供最后「完整论文清单」复用的一句话介绍。
- `topic_signals`：供总生成器提炼「本周趋势判断」的主题信号。
- `warnings`：证据不足、单位线索不足或摘要降级等风险提示。

## 不做什么

- 不抓取 arXiv、PDF、HTML、项目页或代码仓库。
- 不清洗原文、不切分文本、不缓存内容。
- 不计算或校准分数，不决定论文是否入选，不改变排序和阅读层级。
- 不生成整篇周报，不写 YAML front matter、报告导读、本周趋势判断、推荐阅读顺序或完整论文清单表格。
- 不把 `fallback`、阈值、保底、复评流程或旧推荐列表状态写进读者可见正文。

## 小节格式

`section_markdown` 使用以下结构。标题序号由输入 `section_context.index` 决定：

```markdown
### 1. 论文标题

- 发表单位：中文机构名（依据：...）
- 阅读价值评分：...
- 符合维度：...
- 主问题域：...
- 关键支撑技术：...
- 链接：...

**研究问题**

**核心贡献**

**方法框架**

**实验与结果**

**局限与适用约束**

**ADN 启发与阅读价值**
```

## 写作规则

- 面向科研读者和技术负责人，写中文技术周报，不写营销文案。
- 按证据优先级写作：`paper.originalText.excerpt` 优先，其次是 `paper.readingListReview`，再其次是 `paper.analysis`，最后才是 `paper.summary`。
- 如果没有原文，只能基于摘要和已有分析，并在涉及方法、结果和局限的段落写明「基于摘要和已有分析看」。
- 发表单位必须中文化。优先使用 `paper.readingListReview.affiliations` 和 `affiliationEvidence`；如果仍是英文，翻译成通行中文名。不确定时写 `英文原名（中文意译）`。
- 如果单位线索不足，仍写 `发表单位：单位线索不足（依据：...）`，并说明缺少作者区、机构脚注、邮箱域名、致谢或项目页线索。
- 使用读者侧说法 `阅读价值评分`，不要写 `周报复评分`、`复评分`、`复评`、`候选下限`、`内部阈值`、`旧分数` 或 `保底补入`。如果没有提供分数，写 `阅读价值评分：未提供`，不要编造分数。
- 可以展示 `readingListReview.score` 和高匹配维度，但不要把 ICT、电信、网络自治、ADN 等方向匹配写成评分维度或高分依据。
- 如果 `section_context.selection_reason` 是 `fallback`，把论文写进「快速扫读」或低优先级语气，说明短板和适合低优先级阅读的原因，但不要暴露后台保底流程。
- 如果缺少维度详情，写 `符合维度：未提供明确维度`，不要从方向标签倒推出评分维度。
- `研究问题` 写具体问题、重要性，以及和 ADN、网络自治、网络数字孪生或智能体框架的关系。
- `核心贡献` 写相对已有工作新增了什么，不要重复摘要。
- `方法框架` 写方法、模型、系统架构、智能体流程、数据/工具链或关键机制。
- `实验与结果` 写验证方式、主要结论和证据强弱；证据不足时必须保守。
- `局限与适用约束` 至少 2 条，结合数据集、场景假设、评估方式、部署成本、泛化边界、安全可靠或真实网络闭环适配。
- `ADN 启发与阅读价值` 最多 3 条，合并表达阅读价值、关注重点和对华为 ADN 的启发，不要写成读者画像。

## 质量检查

返回前自检：

- 小节没有泄漏内部流程词。
- 发表单位在正文条目里出现，并且是中文或说明线索不足。
- 没有声称读过未提供的全文。
- 每个判断都能被摘要、原文摘录、已有分析或 `readingListReview` 支撑。
- `list_item` 不包含发表单位、分数、符合维度或方向列内容，只保留论文、一句话介绍、阅读级别和链接所需信息。
