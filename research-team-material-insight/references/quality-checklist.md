# 质量检查清单

## 定位、成果与证据

- [ ] 研究方向定位说明了团队聚焦方向、技术演进和核心瓶颈，未堆砌技术名词。
- [ ] 团队身份、研究主题和工程积累均有材料支持，未扩展未经证实的身份或分工。
- [ ] 只保留3至5项高价值成果，默认4项；机制相近或价值重复的成果已合并。
- [ ] 每项成果均回答问题、核心价值、关键技术突破、实验论据与合作意义。
- [ ] 每项成果经过独特性、问题与突破、证据强度、迁移价值和合作可操作性筛选。
- [ ] 基础设施、开源指标和榜单只在能证明成果时使用；未机械单列。
- [ ] 材料事实、能力判断、合作建议和参考示例没有混写。
- [ ] 未将未来方向、业务示例或合作设想写成成熟能力或团队既有项目。
- [ ] 每项核心判断至少包含具体问题对象、差异化机制、证据结果、适用边界、迁移场景中的三项。
- [ ] 成果标题、核心价值和综合判断已通过“名称替换测试”；去掉专有名称后不能套用于大多数团队。
- [ ] “提升效率”“推动演进”“具有重要价值”等通用表达均已补充具体对象、机制、证据和场景价值。
- [ ] 已删除不影响技术判断的普及性背景、行业常识和宽泛趋势描述。

## 范式与合作价值

- [ ] 技术范式判断写明“过去—突破—未来”，且基于材料证据。
- [ ] 范式判断说明了知识、记忆、推理、规划、评测或执行角色的实质变化，而非仅罗列模型名称。
- [ ] 合作方向只保留3至4个与已验证能力高度匹配的具体切入点。
- [ ] 每个合作方向包含技术能力、可迁移场景、具体合作技术和解决问题及价值。
- [ ] 合作方向指向算法、机制、数据、训练、评测或原型，未使用“大平台”“生态”“联合中心”等宽泛表述。
- [ ] 资源研判阶段未擅自加入指标、里程碑、验收口径或复杂边界。

## 图片、来源与语言

- [ ] 图片直接支撑机制或实验结论；无合适图片时未强行插图。
- [ ] 图片优先选择机制图、消融曲线、对照实验、系统闭环或代表性结果，未使用装饰图和低信息量工具清单。
- [ ] 内部证据表记录重要数字和来源定位。
- [ ] 原材料不随成稿共享时，正文、图注和截图均未保留无意义页码或“分享第X页”。
- [ ] 只有存在可靠视频时间戳时才引用视频时间，未编造来源定位。
- [ ] 正文直接陈述技术判断，未反复使用“老师认为”“材料展示”“从材料可以看出”等转述腔。
- [ ] 标题与小标题完整表达主旨；短观点采用“[小标题]：[判断]”结构。
- [ ] 未使用宣传语言、夸张比喻、反问或模板化AI过渡语。

## 月报或聊天观点（如适用）

- [ ] 使用一句总起句概括技术主线和合作价值，默认只保留4个观点。
- [ ] 每点均使用主旨完整的小标题，并严格基于材料证据。

## Word文档（如适用）

- [ ] 采用专业、简单的层级格式，图片、图注、表格与正文没有截断、重叠或异常分页。
- [ ] 已完成渲染和逐页检查，中文字体正常。
- [ ] 修订版使用清晰的新文件名，避免客户端继续打开旧缓存。
