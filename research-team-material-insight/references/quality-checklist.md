# 质量检查清单

## 团队与技术成果

- [ ] 团队或个人名称与用户称谓及材料一致。
- [ ] 团队概况只包含材料支持的身份、研究主题和贡献事实。
- [ ] 技术成果已完成筛选，只保留3至5项，默认4项。
- [ ] 每项成果具有独特性、证据强度、迁移价值或合作可操作性。
- [ ] 机制相近、业务价值重复的技术点已经合并。
- [ ] 基础设施规模、开源星标、工具数量和榜单结果未被机械拆成独立技术点。
- [ ] 除非基础设施本身体现独特闭环能力，否则仅将其作为实验或工程证据。
- [ ] 每项成果清楚说明问题、方法和能够支持的技术判断。
- [ ] 所有证据标签统一为“实验论据”，未混用“执行论据”“量化论据”等名称。
- [ ] 材料事实、能力判断和合作建议没有混写。
- [ ] 未将材料中的未来方向直接写成团队成熟能力。

## 图片与证据

- [ ] 每个技术大点优先配有一张直接支撑观点的原图；无合适图片时未强行添加装饰图。
- [ ] 图片优先选择机制图、消融曲线、对照实验、系统闭环或代表性结果。
- [ ] 未使用仅罗列工具名称、技术价值较低或与大点重复的图片。
- [ ] 图注准确说明图片支撑的技术结论。
- [ ] 重要数字已在内部证据表中记录页码、行号、图表位置或视频时间戳。
- [ ] 原材料不随成稿共享时，正文和图注未出现“分享页码”“分享第X页”。
- [ ] 原材料不随成稿共享时，原PPT截图中的幻灯片页码已去除。
- [ ] 只有视频回看可共享时，未编造不存在的时间戳。

## 合作建议

- [ ] 合作建议只保留3至4个与团队能力高度匹配的方向。
- [ ] 每个方向明确写出“具体合作技术”。
- [ ] 每个方向使用“解决问题及价值”合并说明问题与价值，没有重复拆分。
- [ ] 每个方向指向具体算法、机制、数据、训练方法、评测或执行原型。
- [ ] 未使用“大平台”“生态”“联合中心”等宽泛合作表述替代具体技术。
- [ ] 在资源研判阶段未主动加入指标、里程碑、验收口径和复杂边界。
- [ ] 参考示例如有使用，已明确其不是团队已有成果。

## 语言与结构

- [ ] 正文以技术合作人员的洞察口吻直接陈述观点。
- [ ] 未反复使用“陈老师认为”“陈老师以”“老师将”等转述句式。
- [ ] 未使用“材料展示了”“从材料可以看出”等材料摘要腔。
- [ ] 未加入“以下只保留若干项”“基础设施不再单列”等面向写作者的流程说明。
- [ ] 未使用泛化AI口号、夸张比喻、宣传语言、反问或自问自答。
- [ ] 未滥用“这意味着”“值得关注的是”“更重要的是”等模板化过渡词。
- [ ] 标题和小标题完整表达主旨，未使用“端侧模型判断”等含义模糊的帽子。
- [ ] 默认结构为“团队概况—关键技术成果与洞察—综合判断—合作方向”，没有重复扩写能力章节。
- [ ] 已通读并删除空泛、重复、过度解释和明显AI化的句子。

## 月报简版

- [ ] 使用一句总起句概括核心技术主线和合作价值。
- [ ] 默认只保留4个观点。
- [ ] 每点使用稍长且主旨完整的“帽子”。
- [ ] 每点严格基于材料原文，没有扩展成未经验证的能力。

## Word文档

- [ ] Word文档采用简单、专业的层级格式。
- [ ] 图片、图注、表格和正文没有文字截断、元素重叠或异常分页。
- [ ] 中文字体正常，已完成渲染和逐页检查。
- [ ] 修订版使用清晰的新文件名，避免客户端误开旧缓存。
